## 0. 总图：计算机是一座自动化工厂

**一句话**：CPU 调度，内存暂存，存储持久化，总线运输，外设与现实交互。

```text
存储(Flash/SSD)
   -> 加载
RAM/Cache
   -> CPU 取指/执行/读写
总线(AXI/AHB/APB)
   -> 外设(GPIO/UART/SPI/...)
   -> 人/设备/云 的输入输出
```

### 业务链路示例：按键点亮 LED

```text
按键电平变化 -> GPIO 输入检测 -> 中断控制器 -> CPU 进 ISR
-> 清标志/投递事件 -> 任务处理状态机 -> GPIO 写寄存器
-> 引脚电平变化 -> LED 导通发光
```

**成功定义**：最终“肉眼看见 LED 亮”。  
**常见误判**：日志打印 `led_on success` ≠ 引脚真的翻转。

## 1. 二进制与数据语义

**核心原则**：bit 没有语义，语义来自“解释规则”（类型/协议/寄存器定义）。

- `0x41` 可表示 `65`、`'A'`、`bitmask`、或协议命令字。
- 多字节必须先确认字节序（大小端）。

**最小实验：字节序判断**

```c
uint32_t x = 0x12345678;
uint8_t *p = (uint8_t*)&x;
printf("%02x %02x %02x %02x\n", p[0], p[1], p[2], p[3]);
```

**通过标准**：能解释输出并判断大小端。

## 2. CPU 执行模型：不是跑 C，是跑指令

```text
PC -> Fetch -> Decode -> Execute -> Writeback -> 更新 PC
```

### 调试四件套

- `PC`：是否跑飞到非法地址。
- `SP`：是否超出栈边界。
- `LR`：异常前调用路径。
- 状态寄存器：中断屏蔽位/异常标志。

**最小验证**：崩溃现场先取 `PC/SP/LR + Fault Status`，再看是否越界/未对齐/空指针。

---

## 3. 内存布局：不同区域，不同风险

- `Text/Rodata`：代码与常量，常见问题是跑飞/非法写。
- `Data/BSS`：全局静态区，常见问题是初始化异常或污染。
- `Heap`：泄漏、碎片、UAF。
- `Stack`：溢出、返回地址破坏。

**关键思维**：变量名不等于内存安全，必须看“地址 + 长度 + 生命周期”。

**最小验证**：
- 栈：看水位和哨兵。
- 堆：看最大连续空闲块与分配轨迹。
- 越界：watchpoint/ASan。

---

## 4. 构建流水线：源码如何变成可执行镜像

```text
.c -> 预处理 -> 编译(.s) -> 汇编(.o) -> 链接(ELF/BIN)
```

**常见认知误区**：编译成功 ≠ 可启动 ≠ 业务可用。

### 链接脚本重点

- Flash：向量表、`text`、`rodata`、`data` 初值镜像。
- RAM：`data` 运行区、`bss`、heap、stack。

**最小验证**：检查 map 文件中关键段地址是否符合芯片内存地图。

---

## 5. 启动流程：main 之前的真实世界

```text
上电/复位 -> 向量表取初始 SP 与 Reset_Handler
-> 时钟/内存初始化 -> 拷贝 .data -> 清零 .bss -> 调 main
```

**启动失败排查顺序**：
1. 供电/复位/晶振；
2. 启动模式与入口地址；
3. 向量表首项 SP 是否在 RAM；
4. Reset_Handler 是否在有效代码区。

---

## 6. MMIO 与寄存器：写成功不等于生效

`volatile` 只保证“不被编译器省略”，不保证硬件一定动作。

### GPIO 调试七步

1. 外设时钟；2. 复用；3. 方向/上下拉；4. 写寄存器；5. 读回；6. 看波形；7. 看业务状态。

---

## 7. 中断：紧急响应，不是业务主场

**ISR 原则**：短、快、可重入意识强。  
ISR 只做：清标志、采样关键状态、投递事件。

**避免**：阻塞等待、大量日志、复杂解析、动态内存。

**最小验证**：统计 ISR 耗时分布与队列水位，判断是否丢事件。

---

## 8. DMA + Cache：高吞吐的收益与代价

DMA 降低 CPU 搬运开销，但要处理：
- ring buffer 边界；
- 半传输/全传输中断；
- cache clean/invalidate；
- 对齐与 non-cacheable 策略。

**最小验证**：同一帧在“DMA写后+invalidate后”内容一致可解释。

---

## 9. RTOS：并发是切换，不是同时执行

任务切换触发：中断唤醒、时间片到、阻塞解除、优先级抢占。

**第一问永远是**：这段代码运行在 ISR、回调还是任务上下文？

> 未确认上下文就“盲目加锁”，常导致 ISR 阻塞违规或死锁。

---

## 10. 存储与文件系统：返回成功不代表落盘成功

安全更新建议：

```text
写临时文件 -> fsync(临时文件) -> rename 原子替换 -> fsync(目录)
```

**最终标准**：断电重启后 checksum 仍一致。

---

## 11. 网络与协议：分层定义“成功”

- `send()` 成功：仅代表本地协议栈接收。
- 收到 ACK：仅代表对端某层响应。
- 业务成功：必须有执行结果或状态回读闭环。

**调试法**：把日志拆成 parse / dispatch / execute / report 四段。

---

## 12. 一条完整工程链路（强制背下来）

```text
源码 -> 指令 -> CPU 执行 -> 总线事务 -> 外设寄存器
-> 引脚/介质/报文 -> 对端/用户可见状态
```

遇到问题时，找“第一个不符合预期的层级”，不要跨层猜。

---

## 13. 最小实验路线（验收版）

1. 字节序实验：能解释内存布局。  
2. 栈帧实验：能看出调用深度和返回路径。  
3. 越界实验：能用 ASan/watchpoint 抓到写坏点。  
4. GPIO 翻转：能在示波器上看到稳定波形。  
5. UART IRQ：ISR 计数与接收计数一致。  
6. UART DMA+idle：可正确切分变长帧。  
7. RTOS 队列：队列满策略明确且有统计。  
8. 掉电实验：重启后 hash 一致。  
9. TCP/UDP 回环：区分本地发送成功与业务成功。

## 15. 结语

学习计算机原理的终点不是背术语，而是你能在每一层回答：

1. **谁在读写？**  
2. **何时生效？**  
3. **如何验证？**  
4. **失败停在哪一层？**

只要这四问稳定输出，你就从“会写代码”进入“会做系统工程”。
